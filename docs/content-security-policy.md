# Production Content Security Policy

`public/_headers` is copied to `dist/_headers` by Vite. Cloudflare Pages reads it
and adds an enforcing `Content-Security-Policy` response header, including SPA
fallback routes such as `/login` and `/credits`. No Worker binding changes are needed.
It does not apply to responses generated by Pages Functions or to the Vite dev server.
Other hosting platforms must configure the equivalent response header themselves.

Scripts are restricted to this origin, Apple's sign-in SDK path, and Stripe.js.
Inline scripts, inline event handlers, eval, plugins, base URL changes, and embedding
the admin in another site's iframe are blocked. Inline styles remain allowed for
Radix UI and payment UI; this does not allow inline JavaScript.

Connections allow the Japanese Learning API, Apple sign-in, and Stripe API/fraud
telemetry. Frames allow Apple sign-in and Stripe payment/authentication frames.
Stripe Link, Google Maps/Address Element, and embedded Checkout are not used here
and need their own additional sources if enabled later. If the production API
origin changes, update `connect-src` with `VITE_API_BASE_URL`.

Before release, build and confirm `dist/_headers` exists. After deployment, inspect
the response header for `/`, `/login`, and `/credits`; check the browser console for
CSP violations while signing in, opening a populated management page, logging out,
and completing a Stripe test-mode Apple Pay payment on a supported device. A build
alone does not verify third-party runtime compatibility. Do not make a live charge
just to validate CSP.

References:
- https://developers.cloudflare.com/pages/configuration/headers/
- https://docs.stripe.com/security/guide#content-security-policy
- https://developer.apple.com/documentation/signinwithapple/configuring-your-webpage-for-sign-in-with-apple
